# Overrides and opt-outs

Claude Code loads the shared rules before each project's own instructions, but it does not make either side win when they conflict. The shared rule [`rules/overrides.md`](../../rules/overrides.md) therefore states the precedence explicitly. A project has three ways to differ from the shared rules.

## 1. Stricter additions

A project's `CLAUDE.md` may add rules or tighten shared ones without any marker. Claude follows both.

Example: the shared Git rule lets Claude create an approved commit; a project adds "Run `npm test` before proposing any commit."

## 2. Relaxing or replacing a clause

To relax or replace part of a shared rule, add an entry to a section named exactly `## Overrides of shared rules` in the project's `CLAUDE.md`. Each entry names the rule file and clause and states the replacement. Only that clause changes; the rest of the rule still applies.

```markdown
## Overrides of shared rules
- `documentation.md` › "Doc file names are `UPPER_SNAKE_CASE.md`": this project keeps
  lowercase names for `docs/en/` files generated by the API tool. Reason: the tool fixes the names.
```

Without such an entry, the shared rule wins over a conflicting project instruction, and Claude points out the conflict to the owner. Write `None.` under the heading when there are no overrides, so the section's absence is never ambiguous.

## 3. Opting out of a whole rule file

To stop a whole rule file from loading in one project, add a `claudeMdExcludes` pattern to the project's settings:

- `.claude/settings.json` (committed): the opt-out applies to everyone who works on the project.
- `.claude/settings.local.json` (not committed): a personal opt-out.

```json
{ "claudeMdExcludes": ["**/claude-shared-rules/rules/documentation.md"] }
```

Patterns are glob patterns matched against absolute paths. For a symlinked rule, a pattern may match either the link path (`~/.claude/rules/shared/documentation.md`) or the target (`~/repos/claude-shared-rules/rules/documentation.md`). The pattern above matches the target, so it does not depend on the link name.

Do not use a pattern like `**/.claude/rules/documentation.md`: it would also exclude a project's own rule file of the same name.

`claudeMdExcludes` arrays from different settings files are merged, so a project cannot re-enable a file that another layer excludes.

### Check that the opt-out works

1. Start a new session in the project.
2. Run `/context`. The excluded file must not appear under **Memory files**; the other shared rule files must still appear.

## Personal rules

Rules that only the owner wants and that are not shared go directly in `~/.claude/rules/` as separate files, next to the `shared` link. They follow the same precedence as the shared rules.
