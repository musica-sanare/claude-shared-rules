# Overrides and opt-outs

A project can differ from the shared rules in three ways, from lightest to heaviest:

| Way | Where | Effect |
|---|---|---|
| [1. Stricter additions](#1-stricter-additions) | Project `CLAUDE.md`, no marker | Claude follows both |
| [2. Relaxing or replacing a clause](#2-relaxing-or-replacing-a-clause) | `## Overrides of shared rules` in `CLAUDE.md` | Only that clause changes |
| [3. Opting out of a whole rule file](#3-opting-out-of-a-whole-rule-file) | `claudeMdExcludes` in project settings | The file is not loaded |

This precedence works only because the shared rule [`rules/overrides.md`](../../rules/overrides.md) states it. Claude Code loads the shared rules before project instructions, but does not itself decide which side wins a conflict.

## 1. Stricter additions

Add or tighten rules in the project's `CLAUDE.md`. No marker is needed; Claude follows both.

Example: the shared Git rule lets Claude create an approved commit. A project adds "Run `npm test` before proposing any commit."

## 2. Relaxing or replacing a clause

Add an entry under a section named exactly `## Overrides of shared rules` in the project's `CLAUDE.md`. Each entry names the rule file and clause, then states the replacement and the reason. Only that clause changes; the rest of the rule still applies.

```markdown
## Overrides of shared rules
- `documentation.md` › "Doc file names are `UPPER_SNAKE_CASE.md`": this project keeps
  lowercase names for `docs/en/` files generated by the API tool. Reason: the tool fixes the names.
```

Without an entry, the shared rule wins and Claude points out the conflict to the owner. When a project has no overrides, write `None.` under the heading, so a missing section is never ambiguous.

## 3. Opting out of a whole rule file

Add a `claudeMdExcludes` pattern to the project's settings:

- `.claude/settings.json` (committed): applies to everyone on the project.
- `.claude/settings.local.json` (not committed): applies only to you.

> [!WARNING]
> Do not use a pattern like `**/.claude/rules/documentation.md`. It also excludes a project's own rule file of the same name.

```json
{ "claudeMdExcludes": ["**/claude-shared-rules/rules/documentation.md"] }
```

- Patterns are globs matched against absolute paths.
- A symlinked rule matches by either its link path (`~/.claude/rules/shared/documentation.md`) or its target (`~/repos/claude-shared-rules/rules/documentation.md`). The pattern above matches the target, so it does not depend on the link name.
- `claudeMdExcludes` arrays from all settings files are merged. A project cannot re-enable a file that another layer excludes.

### Check that the opt-out works

1. Start a new session in the project.
2. Run `/context`. The excluded file must be missing from **Memory files**, and the other shared rule files must still appear.

## Personal rules

Rules that only the owner wants go directly in `~/.claude/rules/` as separate files, next to the `shared` link. They follow the same precedence as the shared rules. Optional rules from this repository are opted into the same way; see [Setup › Optional rules](SETUP.md#optional-rules).
