# 上書きとオプトアウト

Claude Code は共有ルールを各プロジェクト自身の指示より先に読み込みますが、両者が競合したときにどちらかを優先させることはしません。そのため、共有ルール [`rules/overrides.md`](../../rules/overrides.md) が優先順位を明記しています。プロジェクトが共有ルールと異なる扱いをする方法は三つあります。

## 1. より厳しい追加

プロジェクトの `CLAUDE.md` では、印を付けずにルールを追加したり、共有ルールを厳しくしたりできます。Claude は両方に従います。

例：共有の Git ルールでは承認済みのコミットを Claude が作成できますが、プロジェクトで「コミットを提案する前に必ず `npm test` を実行する」を追加する。

## 2. 条項の緩和・置き換え

共有ルールの一部を緩めたり置き換えたりするには、プロジェクトの `CLAUDE.md` にある `## Overrides of shared rules` という名前のセクション（見出しはこのとおり）にエントリを追加します。各エントリには、ルールファイル名と条項、置き換える内容を書きます。変わるのはその条項だけで、ルールの残りは引き続き適用されます。

```markdown
## Overrides of shared rules
- `documentation.md` › "Doc file names are `UPPER_SNAKE_CASE.md`": this project keeps
  lowercase names for `docs/en/` files generated by the API tool. Reason: the tool fixes the names.
```

このようなエントリがない場合、競合するプロジェクトの指示よりも共有ルールが優先され、Claude はその競合をオーナーに指摘します。上書きがない場合も見出しの下に `None.` と書き、セクションがないことの意味があいまいにならないようにします。

## 3. ルールファイル全体のオプトアウト

あるプロジェクトでルールファイル全体を読み込ませないようにするには、プロジェクトの設定に `claudeMdExcludes` のパターンを追加します：

- `.claude/settings.json`（コミットする）：そのプロジェクトで作業する全員に適用されます。
- `.claude/settings.local.json`（コミットしない）：個人用のオプトアウトです。

```json
{ "claudeMdExcludes": ["**/claude-shared-rules/rules/documentation.md"] }
```

パターンは絶対パスに対して照合される glob パターンです。シンボリックリンク経由のルールでは、リンク側のパス（`~/.claude/rules/shared/documentation.md`）とリンク先（`~/repos/claude-shared-rules/rules/documentation.md`）のどちらに一致してもかまいません。上のパターンはリンク先に一致するので、リンク名に依存しません。

`**/.claude/rules/documentation.md` のようなパターンは使わないでください。プロジェクト自身の同名のルールファイルまで除外してしまいます。

複数の設定ファイルの `claudeMdExcludes` 配列は統合されるため、別の層で除外されたファイルをプロジェクト側で再び有効にすることはできません。

### オプトアウトが効いているかの確認

1. そのプロジェクトで新しいセッションを開始します。
2. `/context` を実行します。除外したファイルが **Memory files** に表示されず、他の共有ルールファイルは引き続き表示されていることを確認します。

`要確認`：この確認はまだ実施していません。最初にオプトアウトするプロジェクトで実施し、結果をここに記録してください。

## 個人用ルール

オーナーだけが使い、共有しないルールは、`shared` リンクの隣に別ファイルとして `~/.claude/rules/` に直接置きます。優先順位は共有ルールと同じです。
