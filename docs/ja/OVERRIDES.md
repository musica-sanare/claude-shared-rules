# 上書きとオプトアウト

プロジェクトで共有ルールと違うことをしたいときは、次の 3 通りのどれかを使う。上ほど手軽だ：

| 方法 | 書く場所 | 効果 |
|---|---|---|
| [1. 厳しくする・足す](#1-厳しくする足す) | プロジェクトの `CLAUDE.md`（印は不要） | Claude は両方に従う |
| [2. 一部の条項を緩める・置き換える](#2-一部の条項を緩める置き換える) | `CLAUDE.md` の `## Overrides of shared rules` | その条項だけが変わる |
| [3. ルールファイルを丸ごと外す](#3-ルールファイルを丸ごと外す) | プロジェクト設定の `claudeMdExcludes` | そのファイルを読み込まない |

この優先順位が効くのは、共有ルールの [`rules/overrides.md`](../../rules/overrides.md) に書いてあるからだ。Claude Code は共有ルールをプロジェクトの指示より先に読み込むが、両者がぶつかったときにどちらを優先するかまでは決めない。

## 1. 厳しくする・足す

プロジェクトの `CLAUDE.md` にルールを足すか、共有ルールより厳しく書く。印は要らず、Claude は両方に従う。

例：共有の Git ルールでは、承認済みのコミットは Claude が作ってよい。そこへプロジェクト側で「コミットを提案する前に必ず `npm test` を実行する」と足す。

## 2. 一部の条項を緩める・置き換える

プロジェクトの `CLAUDE.md` に `## Overrides of shared rules` という名前ちょうどの節を作り、そこに 1 件ずつ書く。各項目には、ルールファイルと条項、置き換え後の内容、理由を書く。変わるのはその条項だけで、ルールの他の部分はそのまま効く。

```markdown
## Overrides of shared rules
- `documentation.md` › "Doc file names are `UPPER_SNAKE_CASE.md`": this project keeps
  lowercase names for `docs/en/` files generated by the API tool. Reason: the tool fixes the names.
```

ここに書いていない食い違いは共有ルールが勝ち、Claude がオーナーに指摘する。上書きが一つもなければ、見出しの下に `None.` と書いておく。節がないだけだと、書き忘れなのか上書きなしなのか区別できないからだ。

## 3. ルールファイルを丸ごと外す

プロジェクトの設定に `claudeMdExcludes` のパターンを足す：

- `.claude/settings.json`（コミットする）：プロジェクトの全員に効く。
- `.claude/settings.local.json`（コミットしない）：自分だけに効く。

> [!WARNING]
> `**/.claude/rules/documentation.md` のようなパターンは使わない。プロジェクト自身の同名のルールファイルまで外れてしまう。

```json
{ "claudeMdExcludes": ["**/claude-shared-rules/rules/documentation.md"] }
```

- パターンは glob で、絶対パスと照合される。
- シンボリックリンク経由のルールは、リンク側のパス（`~/.claude/rules/shared/documentation.md`）でもリンク先のパス（`~/repos/claude-shared-rules/rules/documentation.md`）でも一致する。上の例はリンク先に一致させているので、リンク名が変わっても効く。
- 複数の設定ファイルの `claudeMdExcludes` は合算される。別の層で外されたファイルを、プロジェクト側で戻すことはできない。

### 外れたことを確かめる

1. プロジェクトで新しいセッションを開く。
2. `/context` を実行する。**Memory files** に外したファイルがなく、他の共有ルールは残っていれば成功。

`要確認`：この確認はまだ一度もしていない。最初にオプトアウトするプロジェクトで試し、結果をここに書く。

## 個人用のルール

オーナーだけが使い、共有しないルールは、`~/.claude/rules/` に別ファイルとして直接置く（`shared` リンクの隣）。優先順位は共有ルールと同じ扱いになる。このリポジトリのオプションのルールも同じ方法で使う（[セットアップ › オプションのルール](SETUP.md#オプションのルール)）。
